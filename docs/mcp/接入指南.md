# MCP 集成 · 接入指南

本系统通过 **MCP（Model Context Protocol）** 把「企业级 RAG 知识库」暴露为标准工具集，
任何支持 MCP 的客户端（Claude Code / Claude Desktop / Cursor 等）都能直接查询知识库、
提问并获得带引用的答案。

> 原则：**只复用、不重写**。所有 MCP 工具直接调用现有 RAG 服务
> （`retriever` / `rag_chain` / `agent` / `router`），与网页端 `/api/chat` 共用同一套检索、生成逻辑。

---

## 1. 工具清单

| 工具 | 说明 | 适用场景 |
| --- | --- | --- |
| `kb_search` | 混合检索知识库，返回命中片段 + 来源文档 + 相似度 | 需要核对原文、自行组织回答 |
| `kb_ask` | 知识库 RAG 问答，返回答案 + 引用来源 | 一步得到带引用的最终答复 |
| `kb_agent` | 通用 AI 助手（意图路由）：计算 / 天气 / 日历 / 知识库 | 非知识库类通用问题 |
| `kb_stats` | 知识库统计：文档数 / 就绪数 / 分块数 / 向量点数 | 了解知识库规模 |
| `kb_documents` | 文档列表（可按状态过滤） | 查看已上传文档 |

全部为**只读**工具，不暴露写入 / 删除 / 管理能力。

## 2. 两种运输方式

| 运输 | 命令 | 适用 |
| --- | --- | --- |
| **stdio** | `python backend/run_mcp_server.py` | 本机直连（Claude Code / Desktop），零网络、最常用 |
| **Streamable HTTP** | `python backend/run_mcp_server.py --transport http --port 8001` | 远程访问 / Cursor 等支持 HTTP 的客户端 |

## 3. 快速开始

### Claude Code（本仓库已内置配置）

项目根目录的 [`.mcp.json`](../../.mcp.json) 已声明 `rag-kb` 服务器，重启 Claude Code 后
工具自动可用（需在会话中确认接入）。脚本会自动引导到 `backend/.venv` 的解释器，无需手动切环境。

在 Claude Code 里即可直接问，例如：
> “用 rag-kb 检索知识库：充电宝支持多少瓦快充？”
> “查询知识库统计”

### Claude Desktop

编辑配置文件（Windows：`%APPDATA%\Claude\claude_desktop_config.json`）：

```json
{
  "mcpServers": {
    "rag-kb": {
      "command": "python",
      "args": ["backend/run_mcp_server.py"],
      "cwd": "D:/LangChainRAG项目"
    }
  }
}
```

### Cursor / 其他支持 HTTP 的客户端

先启动 HTTP 服务：

```bash
cd backend
.venv/Scripts/python.exe run_mcp_server.py --transport http --host 127.0.0.1 --port 8001
```

客户端 MCP 服务器 URL 填：`http://127.0.0.1:8001/mcp`

## 4. HTTP 鉴权（可选）

在 `backend/.env` 设置 `MCP_HTTP_TOKEN` 后，HTTP 模式要求请求头：

```
Authorization: Bearer <你的 MCP_HTTP_TOKEN>
```

未设置则 HTTP 模式不鉴权（仅建议本机使用）。

## 5. 验证

前置：启动 Qdrant（`infra/qdrant/qdrant.exe`，或 `dev_start.bat`）。

```bash
# stdio 全协议冒烟：会真实调用 5 个工具（含 LLM 问答）
backend/.venv/Scripts/python.exe scripts/test_mcp_stdio.py

# 需先另起终端：python backend/run_mcp_server.py --transport http --port 8001
backend/.venv/Scripts/python.exe scripts/test_mcp_http.py
```

单元测试：`backend/.venv/Scripts/python.exe -m pytest backend/tests/test_mcp.py`

## 6. 云端部署注意

- MCP 复用后端进程的向量模型（ONNX），**stdio 本地使用零额外内存**。
- 云端远程 HTTP 需要独立进程（`--transport http`），会**二次加载向量模型**；
  1.6G 小机内存紧张，建议以本地 stdio 为主。若需远程，先在 `deploy/nginx.conf`
  打开 `/mcp` 反代注释块，并保证服务器内存余量。
- 工具只读 + 可选 Bearer Token，未暴露管理接口，风险可控。

## 7. 实现结构

```
backend/app/mcp/server.py      # MCPServer 定义 + 5 个工具（复用现有 RAG 服务）
backend/run_mcp_server.py      # 入口：stdio / HTTP 双运输 + venv 自动引导
scripts/test_mcp_stdio.py      # stdio 裸协议冒烟（initialize/tools/list/call）
scripts/test_mcp_http.py       # HTTP 冒烟（initialize/tools/list/call）
backend/tests/test_mcp.py      # pytest 单元测试（注册 / schema / 降级行为）
.mcp.json                      # Claude Code 一键接入配置
```
